## 1. Synthesis — what the research collectively says

### "Enhance is slow" — the model is NOT the bottleneck

R2 confirmed and R1 corroborated: the model is doing more work than it needs to because of how WE shaped the input. Five fixable bottlenecks dominate the wall-clock; none requires a model swap. R1's encoder-decoder candidates (CoEdIT/GECToR) are blocked by mlx-swift-lm 3.31.3 type registry + license issues anyway. The two real strategic levers, in cost order:

1. **Pipeline fixes (W11.A)** — cheap, high-yield, no new dependencies.
2. **Speculative decoding (W11.B)** — additive 2-3× exact-equivalence speedup on existing Qwen3 lineup; new SPM dep, focused refactor.
3. **Apple Foundation Models (W11.C, optional)** — `@available(macOS 26.0, *)` conditional path; OS-bundled 3B AFM with sub-150ms TTFT; gated availability is a product call.

### "WhisperFlow features" — target is **Wispr Flow** (`wisprflow.ai`), not the clone

R3 narrowed to five P0 features that close the bidirectional-voice-editing + power-user gap. Each maps to existing VoiceInk primitives we just haven't wired together. The "Auto Cleanup levels + diff + undo" P0 directly answers the user's "enhance is bad" complaint by giving them a dial + visibility instead of the current binary toggle.

### "App aesthetic still off" — vocabulary IS captured, but not consistently applied

R4 confirmed the floating-bar/`Glass*` vocabulary is well-defined in code (`HaloMaterial.swift`, `GlassCard.swift`, `GlassChip.swift`, `Palette.swift`, `AdaptiveGlassBackground.swift`). The W1-W8 work landed it on most surfaces. The remaining offenders are concentrated: MetricsView is the worst (first surface a new user sees, hosts the dashboard, breaks the language entirely), then a tail of surfaces still on `Form { Section }` from the v1 layout, then AI Models cards that bypass `GlassCard`, then the History window that never got the W8 wallpaper-glass treatment.

## 2. W11 — Enhance speed: real fix

**Goal:** real-world dictation enhance feels instant on M-base 32 GB.
**Baseline missing:** repo currently has zero captured `🦾 enhance: total=…s` numbers. **GROUND-TRUTH GATE** — before any code lands, capture five `total=` lines on the user's machine using the current build (per R2 §"ground-truth recommendation"). This becomes the regression baseline.

### W11.A — Pipeline fixes (highest leverage, no new deps)

Five P0 fixes from R2 §1, ordered by yield:

| Fix | Where | Yield estimate | Risk |
|---|---|---|---|
| **A1.** Add MLX to `ModelPrewarmService.shouldPrewarm()` switch + trigger warm on app launch + on `NSWorkspace.didWakeNotification` + on recording start | `VoiceInk/Services/ModelPrewarmService.swift:107-115` + `VoiceInkEngine.swift` | -1.5 to -4s cold spike → first enhance after idle | LOW — additive |
| **A2.** Short-transcript fast-path: drop wrapper + use minimal cleanup-only system prompt for inputs ≤30 tokens | `AIEnhancementService.getSystemMessage(for:)` `:148-205` | Cuts ~25× system:user ratio → -30-50% prefill on short dictations | LOW — content-aware branch |
| **A3.** KV-cache reuse for system prefill across calls | `MLXProvider.enhance(...)` `:59-146` (mlx-swift-lm 3.31.3 PR #155) | Second-onward enhance skips system prefill entirely → -150-400ms ttft | MED — requires careful invalidation on prompt switch |
| **A4.** `GenerateParameters(temperature: 0.0)` (drop `topP`) → `ArgMaxSampler` route | `MLXProvider.swift:94-98` | -5-15ms per generation; compounds over 50-200 tokens | LOW — quality-neutral on cleanup |
| **A5.** Wall-clock generation timeout (use existing `EnhancementTimeoutSeconds` AppStorage, currently only applies to remote APIs) | `MLXProvider.swift:106-124` | Caps worst-case 16-64s rambling outputs at the user's preferred ceiling | LOW |

Plus two cheap secondaries:
- **A6.** Make `idleEvictSeconds` configurable via `@AppStorage("MLXIdleEvictSeconds", default: 1800)` (10 min → 30 min default), expose in MLX picker. Or drop idle eviction entirely on 32 GB+ machines.
- **A7.** Drop `max_tokens` floor from 192 → 96 for transcripts under ~30 chars; ceiling from 768 → 512.

**Packet shape:** single packet, sequential implementation (planner → coder → reviewer). Each fix is a localized edit; combined diff likely <300 LOC.

### W11.B — Apple Foundation Models (NEW PRIMARY PATH per Q1=b)

Bump deployment target to **macOS 26.0**. AFM becomes the primary enhance path; MLX is fallback for users without Apple Intelligence enabled (M1+ Mac with AI off in System Settings).

- **Project:** bump `MACOSX_DEPLOYMENT_TARGET` in `VoiceInk.xcodeproj/project.pbxproj` from 14.4 → 26.0. Drops Macs on Sonoma and earlier — confirm acceptable via Sparkle telemetry (or accept the cut).
- **Path detection:** at app launch, probe `SystemLanguageModel.default.isAvailable`. If true → AFM primary. If false (Apple Intelligence disabled / unsupported chip) → MLX fallback.
- **AFM enhance:** `AIEnhancementService.enhance(...)` routes through `LanguageModelSession(instructions: systemPrompt).streamResponse(to: userPrompt)`. Call `session.prewarm()` on app launch + on recording start (mirrors W11.A1 prewarm logic).
- **System prompt trim still applies** (W11.A2) — AFM also pays prefill cost on long instructions.
- **Constrained decoding:** AFM daemon already runs constrained decoding for guided generation; explore `Generable` macros if any structured-output prompts benefit (opt-in, not blocking).
- **Safety filters:** AFM has been observed to refuse some legitimate prompts. Fallback to MLX path on refusal, log the trigger so we can tune our prompt scaffolding.
- **Yield:** sub-150ms TTFT with prewarm; quality matches Qwen3-4B class on cleanup.

**Packet shape:** single packet, sequenced AFTER W11.A. New `AFMProvider.swift` actor parallel to `MLXProvider.swift`. Pre-merge hardware test on user's M-base + a non-AI-enabled Mac (or AI temporarily disabled in Settings) to validate fallback.

### W11.C — Speculative decoding (MLX fallback path optimization, opt-in)

Per Q3=c: single Settings switch "Use speculative decoding" off-by-default; only relevant when user is on the MLX fallback path. Add `mlx-community/speculative-decoding` Swift SPM dep + `Qwen3-0.6B-4bit` (335 MB) hidden draft model auto-downloaded when switch flips on.

- **Refactor:** `MLXProvider.enhance(...)` branches on the toggle: off → existing `container.generate(...)`; on → `SpeculativeDecoding.generate(prompt:draftModelId:targetModelId:)`.
- **Settings UI:** new toggle in MLX picker section.
- **Quality:** EXACT equivalence by construction.
- **Yield:** R1 cites 2-3× target-model generation speedup.
- **Sequencing:** ship AFTER W11.A and W11.B. With AFM primary, this benefits a smaller user fraction (those without Apple Intelligence) but is still meaningful for that segment.

**Packet shape:** single packet. Larger diff — adds dep, adds hidden registry entry, refactors generate path, adds toggle. Pre-merge hardware test on a non-AI-enabled Mac mandatory.

## 3. W12 — Wispr Flow feature parity (essentials)

**Goal:** close the bidirectional-voice-editing + power-user gap; preserve VoiceInk's strengths (local, configurable, OSS, multi-recorder UI, paid-once).

Five P0 features from R3 §1, ordered by user-leverage × build cost:

### W12.A — Auto Cleanup levels + diff view + Undo AI edit
**Why first:** directly addresses the user's "enhance is bad" complaint by replacing binary toggle with a 4-level dial + visibility into what changed + recovery. Builds trust in the AI enhance.

- **Replace** `isAIEnhancementEnabled: Bool` per PowerMode with `enhanceLevel: EnhanceLevel` (None / Light / Medium / High).
- **Wire** `WordDiffEngine` (already exists) into a result UI: side-by-side diff + revert.
- **Persist** raw transcript alongside enhanced (currently only enhanced is kept).
- **UI:** likely lives in `EnhancementSettingsView` (level picker) + History detail view (diff + revert).

### W12.B — Command Mode (highlight + voice rewrite)
**Why next:** Wispr's #1 differentiator per reviews; primitives all exist (`SelectedTextService`, `AIEnhancementService`, MLX path) but never wired into a global hotkey + replace-selection action.

- New hotkey (default proposal: `Fn+E` for "Edit Selection"; configurable; rebindable via `KeyboardShortcuts`).
- Capture selection → record voice → enhance with the spoken instruction as the prompt → paste replacement → keep undo state.

### W12.C — Voice Snippets (text expansion)
**Why third:** zero coverage today; aText/Raycast users won't switch without it.

- New model: `Snippet { trigger: String; expansion: String; tags: [String] }`.
- Persistence: add to existing `ImportExportService` codepath.
- Activation: post-transcription token-stream filter that detects triggers and emits expansion (open Q4 — alternative is in-prompt activation).
- UI: settings page (CRUD), import/export.

### W12.D — Hands-free / continuous mode + VAD + voice "press enter"
**Why fourth:** accessibility-critical (Parkinson's users specifically cited Wispr for this) + long-form dictation use case.

- Add toggle/double-tap activation that flips into continuous mode.
- VAD (voice activity detection) auto-stop with configurable silence threshold.
- Voice command "press enter" / "submit" / "send it" — strips the trigger phrase from output then triggers configured `autoSendKey`.
- Session length cap (proposal: 20 min match Wispr).

### W12.E — Scratchpad
**Why last:** highest dependency surface (new window, multi-tab, version history, paste-fallback wiring) and not in the critical use case the user cited.

- New window: `⌥+S` opens a dictation-into-place editor.
- Multi-tab + auto-save + 50-version history with restore.
- Doubles as the paste-fallback target when `CursorPaster` fails.

**P1 features queued for later** (not in W12): Backtrack prompt update, recipient-aware tone via `ScreenCaptureService`, banking-app auto-pause, Variable Recognition + File Tagging for Cursor/Windsurf, first-run onboarding.

**Packet shape:** five sub-packets (A through E), parallelizable in pairs (A+C have no overlap; B+D share recorder-state code so sequence those). Per `feedback_skip_per_packet_builds.md`: single integration build at merge time.

### Q1 — W11.C: Apple Foundation Models deployment-target call

**Options:**
- **(a) Dual-path (lead's recommendation).** Keep min-target macOS 14.4. Add `@available(macOS 26.0, *)` branch in `AIEnhancementService` that routes to AFM when present, else MLX. Newer users get sub-150ms TTFT for free; older users keep current behavior.
- **(b) Bump deployment to macOS 26.0.** Drops `~30-50%` of user base (rough Mac install-base estimate; verify via Sparkle telemetry if we have it). AFM-first.
- **(c) Defer W11.C entirely.** Ship only W11.A + W11.B; revisit AFM in 6-12 months when adoption climbs.

### Q2 — W11.A.6: Idle eviction policy on 32 GB+ machines

**Options:**
- **(a) Make `idleEvictSeconds` configurable, default 1800 (30 min).**
- **(b) Default to `.infinity` on machines with ≥16 GB free; configurable.**
- **(c) Keep 600s default.**

Lead leans (a) — explicit user control + sensible default that matches user's "I dictate every 20 min" usage pattern.

### Q3 — W11.B: Qwen3-0.6B visibility

**Options:**
- **(a) Add `Qwen3-0.6B-4bit` as a user-visible "Ultra-Fast" registry tier** AND use it as the speculative draft. Doubles as the no-spec-decode option for short-transcript-only users.
- **(b) Hidden draft-only entry.** No registry row; downloaded automatically when speculative decoding is chosen.
- **(c) User toggleable: Settings → AI Enhancement → MLX → "Use speculative decoding" switch.** Off → just Qwen3-4B. On → spec-decode with hidden 0.6B draft.

Lead leans (c) — gives users a single-flag escape hatch if spec-decode misbehaves on their hardware.

### Q4 — W12.C: Voice Snippets activation strategy

**Options:**
- **(a) Post-transcription token-stream filter.** Trigger detection runs after enhance; expansion injected into final output. Pro: model never sees triggers. Con: misses if user mid-sentence-pivots.
- **(b) In-prompt activation.** Pass triggers as part of the enhance system prompt so the model itself expands. Pro: contextual. Con: token bloat (R2 §H6 just told us prompts are too big!), prompt-injection risk.
- **(c) Pre-enhance regex filter on raw transcript.** Strip triggers before enhance, splice expansions back in afterward. Pro: avoids both downsides above.

Lead leans (c) — symmetric with W11.A2 short-prompt fast-path; keeps the LLM blind to trigger logic.

### Q5 — W12.B: Command Mode hotkey when `Fn` is taken

Wispr uses `Fn+Space` for hands-free; `Fn` for push-to-talk. VoiceInk's hotkey assignment may collide with the user's existing PTT binding.

**Options:**
- **(a) Default to `Cmd+Shift+E`** (Edit Selection). Configurable.
- **(b) Use a chord — hold PTT hotkey + tap E.** Re-uses the muscle memory.
- **(c) Toolbar/menubar item only** for v1; add hotkey in v2 once UX is validated.

Lead leans (a) — predictable, configurable.

### Q6 — W12.A: Auto Cleanup levels — 4 or 3?

Wispr has 4 (None / Light / Medium / High). VoiceInk currently has 2 (off / on).

**Options:**
- **(a) 4 levels** — match Wispr. None / Light filler-removal / Medium grammar+filler / High full-rewrite-with-style.
- **(b) 3 levels** — None / Light / Full. Simpler picker; less prompt scaffolding.
- **(c) Keep binary, but add a separate "tone" picker** (Casual / Formal / Excited / Email / Slack).

Lead leans (a) — matches user mental model from Wispr; level 0 + level 3 are the two real workflows; levels 1 + 2 are useful intermediate stops.

### Q7 — W13: Menubar dropdown — system-default or floating-bar style?

R4 flagged this as ambiguous. The menubar dropdown currently uses macOS system styling.

**Options:**
- **(a) Apply floating-bar style.** Same `glassPanel()` chrome; consistent vocabulary.
- **(b) Keep system-default.** Menubar dropdowns have OS-level expectations users are sensitive to.

Lead leans (b) — menubar dropdowns are a system contract; apps that override them feel off in subtle ways. But user picks.

### Q8 — W13: History window — separate window or embed in main app?

**Options:**
- **(a) Keep separate, fix W8 wallpaper-glass flags.** Minimal change, preserves current UX.
- **(b) Collapse into main ContentView as a destination.** Removes a window class; matches sidebar IA.

Lead leans (a) — separate window is useful for the "review past dictations while still using foreground app" pattern. But this is a real product call.

### Q9 — W13: Hero gradient — keep or drop?

`MetricsContent.heroSection` uses a controlAccentColor gradient that R4 flagged as breaking the language.

**Options:**
- **(a) Keep, but switch to `Palette.accent` glow.** Gradient stays; color aligns.
- **(b) Drop entirely.** Gradient is decorative; remove for less visual noise.

Lead leans (a) — Dashboard benefits from a small visual focal point; switching to `Palette.accent` aligns vocabulary.
